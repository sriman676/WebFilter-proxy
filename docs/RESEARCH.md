# Research Basis (how published work shaped the design)

|---|---|---|---|---|
| R-01 | J. Kettle, "HTTP Desync Attacks: Request Smuggling Reborn" (PortSwigger, Black Hat/DEF CON 2019) https://portswigger.net/research/http-desync-attacks ; "HTTP/1.1 must die: the desync endgame" (2025) https://portswigger.net/research/http1-must-die ; coverage of client-side desync/first-request routing (Dark Reading) | Front/back-end disagreement on message length (CL.TE, TE.CL, TE.TE, plus HTTP/2 downgrade) lets attackers splice requests into other users' traffic over shared connections; proxies that validate or route only the first request on a connection are exploitable; author argues HTTP/1.1 boundaries are inherently weak and new variants keep appearing; forward proxies add extra smuggling risk | D-06 (no h2 downgrade), D-07 (no shared upstream sockets), D-08 (strict rejection), D-10 (filter every request), R1-R15 | SM-01..25, I-20..28, E-33, PT-2.1/2.2/2.4, F-04 |
| R-02 | Z. Durumeric et al., "The Security Impact of HTTPS Interception" (NDSS 2017) https://www.ndss-symposium.org/ndss2017/ndss-2017-programme/security-impact-https-interception/ | Interception middleboxes and client-side security products as a class frequently reduce connection security versus direct connections, and a significant share introduce serious flaws such as incorrect certificate validation | D-19/D-20: always validate upstream certs, TLS>=1.2, modern defaults, never weaker than direct; no verification-skip in release builds; security-grade comparison proxied vs direct | E-17, PT-4.3, PT-4.8, PT-8.2 |
| R-03 | Claroty Team82 & Snyk, "Exploiting URL Parsing Confusion" (2022) https://claroty.com/team82/research/exploiting-url-parsing-confusion ; Orange Tsai, "A New Era of SSRF" (Black Hat/DEF CON 2017) https://infocondb.org/con/def-con/def-con-25/a-new-era-of-ssrf-exploiting-url-parser-in-trending-programming-languages | Different URL parsers interpret the same string differently (scheme, slash, backslash, URL-encoding confusion); when the validator and the requester use different parsers, filters and SSRF protections are bypassed | D-09 dual-parser differential check, rebuild request from normalized fields, reject backslashes/odd slashes/userinfo/non-canonical IPs; `url_bypass_cases.tsv` | U-001..055, P-01, P-06, F-01, PT-1.1, PT-2.3 |
| R-04 | J. Chen et al., "Host of Troubles: Multiple Host Ambiguities in HTTP Implementations" (ACM CCS 2016, pp. 1516-1527) | Implementations disagree on multiple Host headers, whitespace-padded Host, and absolute-URI vs Host precedence; this enables cache poisoning and firewall/WAF bypass; RFC 7230 5.4 requires rejecting inconsistent hosts | R7 (single Host, must match absolute-form authority), D-22 | SM-11/12, PT-2.5 |
| R-05 | IETF RFC 9849, "TLS Encrypted Client Hello" (March 2026) https://datatracker.ietf.org/doc/rfc9849/ ; operator-impact discussions (ECH and content filtering) | ECH encrypts the ClientHello so SNI-based inline filtering loses visibility; DNS/explicit-proxy and decrypting approaches are less affected | D-21: in explicit mode the CONNECT authority drives filtering; log `ech_present`; recommend disabling QUIC; no ECH support on our listener | E-34, PT-4.5, PT-4.7 |

| R-07 | OWASP Web Security Testing Guide; NIST SP 800-115 (Technical Guide to Information Security Testing); PTES | Structure for planning, executing and reporting security tests | PENTEST_PLAN method, report/finding templates | all PT-* |
| R-08 | Reports of AI-assisted desync discovery (PortSwigger "http-terminator", 2026, per press coverage) | Novel desync vectors are expected to keep emerging | Prefer strict parsing + fuzzing + differential testing over fixed payload lists; keep `smuggling_cases.md` growing | F-04, PT-2.17 |
| R-09 | hudsucker crate (docs.rs) and its forks | Rust MITM proxy library on hyper/rustls/rcgen; evaluated and rejected as the engine because framing/parsing control is the core security requirement and the crate has version churn and forks | D-05 first-party `proxy::http1` core | SPEC 4.15, X-01..X-03, PT-2.19 |
| R-10 | HTTP/2 DoS research: Rapid Reset (CVE-2023-44487, 2023); CONTINUATION Flood (B. Nowotarski, 2024; many CVEs e.g. CVE-2024-27316, CVE-2023-45288, CVE-2024-28182) https://www.securityweek.com/new-http-2-dos-attack-potentially-more-severe-than-record-breaking-rapid-reset/ ; MadeYouReset (CVE-2025-8671) and the PING/SETTINGS/empty-DATA flood family (CVE-2019-9512/9515/9518) as summarized in proxy-vendor mitigation write-ups https://www.clever.cloud/blog/engineering/2026/05/29/sozu-2-0-reverse-proxy-programmable-edge/ | Cheap client-driven frame patterns (stream reset loops, unterminated header blocks, control-frame storms) exhaust CPU/memory of h2-capable proxies; mitigations are rate/size limits and dedicated violation counters | D-45, SPEC 4.16 flood limits incl. server-caused resets, `h2_flood` events and stats | I-h2-flood, E-42, PT-6.1..6.3, F-10 |
| R-11 | Transparent proxy practice: iptables REDIRECT + SO_ORIGINAL_DST vs TPROXY (e.g. https://wpc.unveiltech.com/blog/tproxy-vs-redirect.html ; Envoy original_dst documentation) | Transparent proxies must recover the original destination from the kernel (SO_ORIGINAL_DST/conntrack for REDIRECT, socket local address for TPROXY); NAT redirection hides the destination from naive code and interacts badly with ECH; connections that were not redirected must not be treated as valid | D-41/D-42, SPEC 4.17 (reject un-redirected connections, original-IP upstream, host_verify, ECH action); TPROXY deferred | E-44..E-51, PT-7.x |
| R-12 | abuse.ch terms of use (effective 2025-11-04) https://abuse.ch/terms-of-use and URLhaus API/feed pages https://urlhaus.abuse.ch/api/ | Platforms are free under fair-use terms with eligibility conditions; the URLhaus plain-text list is regenerated every 5 minutes and must not be fetched more often; formats include plain-text URLs, CSV, hostfile and RPZ; some sources may require registration | D-52: feeds disabled by default, terms verified and recorded before enabling, min refresh 300 s, optional API-key header | E-59, E-62, PT-10.2 |
| R-13 | clamd manual (INSTREAM) https://man.archlinux.org/man/extra/clamav/clamd.8.en | INSTREAM sends chunks of a 4-byte big-endian length plus data, terminated by a zero-length chunk; exceeding StreamMaxLength gets an error and the connection is closed | D-54, SPEC_EXT_POLICY P4 | E-63..E-65, PT-10.5, F-15 |
